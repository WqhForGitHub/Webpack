# 78. exclude node_modules

纯 webpack 演示 `exclude` / `include` 对 loader 的影响。

## 原则

- `babel-loader`、`ts-loader` 这类「重 loader」一定要排除 `node_modules`。
- 推荐双保险写法：

```js
{
  test: /\.js$/,
  include: path.resolve(__dirname, 'src'),
  exclude: /node_modules/,
  use: 'babel-loader',
}
```

## 实验

```bash
npm install
npm run build:bad     # 不加 exclude：babel 处理 lodash 全量源码，编译慢
npm run build:good    # 加 exclude：只编译 src，编译快
```

对比终端打印的耗时，可以观察到明显差距（lodash 越大差距越明显）。

## 为什么不能丢掉 exclude？

- 第三方库通常已经发布过 ES5/CJS 版本，无需再次 babel 编译；
- 编译后还可能引入 polyfill/regenerator runtime，反而让产物变大；
- node_modules 的源码动辄上百兆，重复编译就是浪费 CPU。
