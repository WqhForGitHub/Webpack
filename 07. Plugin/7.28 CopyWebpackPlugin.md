将已存在的单个文件或整个目录复制到构建目录。
# 入门

首先，您需要安装 `copy-webpack-plugin`：
```shell
npm install copy-webpack-plugin --save-dev
```
然后将插件添加到你的 `webpack` 配置中。例如：
**webpack.config.js**
```javascript
const CopyPlugin = require('copy-webpack-plugin');

module.exports = {
	plugins: [
		new CopyPlugin({
			patterns: [
				{ from: 'source', to: 'dest' },
				{ from: 'other', to: 'public' }
			]
		})
	]
}
```
>`copy-wbepack-plugin` 并非设计用于复制构建过程中生成的文件，而是用于复制构建过程中已存在于源代码树中的文件。

>如果您希望 `webpack-dev-server` 在开发期间将文件写入输出目录，您可以使用 `writeToDisk` 选项或 `write-file-webpack-plugin` 强制执行。

>您可以从资产对象中获取原始源文件名。

| ---------- | ------------------------- | ----------- |
| `patterns` | `{Array<String\|Object>}` | 为插件指定文件相关模式 |

## Patterns

| 姓名                 | 类型                   | 默认                                          | 描述                                                                                    |
| ------------------ | -------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------- |
| `from`             | `{String}`           | `undefined`                                 | 文件复制源的全局路径或路径                                                                         |
| `to`               | `{String, Function}` | `compiler.options.output`                   | 输出路径                                                                                  |
| `context`          | `{String}`           | `options.context, compiler.options.context` | 决定如何解释`from`路径的路径                                                                     |
| `globOptions`      | `{Object}`           | `undefined`                                 | 传递给 glob 模式匹配库的选项，包括 `ignore` 选项                                                      |
| `filter`           | `{Function}`         | `undefind`                                  | 允许筛选已复制的资源                                                                            |
| `toType`           | `{String}`           | `undefined`                                 | 确定选项`to`什么，目录、文件还是模板                                                                  |
| `force`            | `{Boolean}`          | `false`                                     | 覆盖`compilation.assets` 中已有的文件（通常由其他插件/加载器添加）                                          |
| `priority`         | `{Number}`           | `0`                                         | 允许您指定复制优先级                                                                            |
| `transform`        | `{Object}`           | `undefined`                                 | 允许修改文件内容。启用`transform`缓存。您可以使用`{transform: { cache: { key: 'my-cache-key' } }}`来使缓存失效 |
| `transformAll`     | `{Function}`         | `undefined`                                 | 允许您修改多个文件的内容，并将结果保存到一个文件中                                                             |
| `noErrorOnMissing` | `{Boolean}`          | `false`                                     | 不会因缺少文件而产生错误                                                                          |
| `info`             | `{Object, Function}` | `undefined`                                 | 允许添加资产信息                                                                              |
### from
类型: `String` 默认值: `undefined`
全局变量或文件复制路径。全局变量支持快速全局变量模式语法。全局变量只能是 `string`。
**webpack.config.js**
```javascript
module.exports = {
	plugins: [
		new CopyPlugin({
			pattern: [			
				'relative/path/to/file.ext',
		        'relative/path/to/dir',
		        path.resolve(__dirname, 'src', 'file.ext'),
		        path.resolve(__dirname, 'src', 'dir'),
		        '**/*',
		        {
		          from: '**/*',
		        },
			// If absolute path is a `glob` we replace backslashes with forward slashes, because only forward slashes can be used in the `glob`
		        path.posix.join(
		          path.resolve(__dirname, 'src').replace(/\\/g, '/'),
		          '*.txt'
		        ),
			]
		})
	]
}
```
**适用于 windows**
```javascript
module.exports = {
	plugins: [
		new CopyPlugin({
			patterns: [
				{
					from: path.resolve(__dirname, 'file.txt')
				}
			]
		})
	]
}
```
但是，在 `glob` 表达式中应该始终使用正斜杠。请参阅 fast-glob 手册。
```javascript
module.exports = {
	plugins: [
		new CopyPlugin({
			patterns: [
				{				
					// If absolute path is a `glob` we replace backslashes with forward slashes, because only forward slashes can be used in the `glob`
					from: path.posix.join(
						path.resolve(__dirname, 'fixtures').replace(/\\/g, '/'),
						'*.txt'
					)
				}
			]
		})
	]
}
```
`context` 行为取决于 `from`（`global`、`file`或 `dir`）的类型。更多 `examples`

### context

类型：`String` 默认值：`options.context, compiler.options.context`

决定如何解释 `from` 路径的路径。

**webpack.config.js**
```javascript
module.exports = {
	plugins: [
		new CopyPlugin({
			patterns: [
				{
					from: 'src/*.txt',
					to: 'dest/',
					context: 'app/'
				}
			]
		})
	]
}
```
`context` 选项可以是绝对路径或相对路径。如果 `context` 是相对路径，则会根据 `compiler.options.context 将其转换为绝对路径。`

此外， `context` 有助于理解搜索结果。而且，他也被认为适合担任这个角色。

要确定要从中找到的资源复制到目标文件夹的结构，可以使用 `context` 选项。

如果 `from` 是一个文件，那么 `context` 就等于该文件所在的目录。因此，结果将只有文件名。

如果 `from` 是一个目录，则 ` `context` 与 `from` 相同，等于目录本身。在这种情况下，结果将是相对于指定目录的已找到文件夹和文件的层级结构。

如果 `from` 是一个 glob 类型，那么无论 `context` 选项如何，结果都将是 `from` 选项中指定的结构。

更多 [`examples`](https://webpack.docschina.org/plugins/copy-webpack-plugin/#examples)

### globOptions

 类型：`Object` 默认值：`undefined`

允许配置插件使用的 glob 模式匹配库。 [请参阅支持的选项列表](https://github.com/sindresorhus/globby#options) 。 要从选择中排除文件，您应该使用 [globOptions.ignore 选项。](https://github.com/mrmlnc/fast-glob#ignore)

**webpack.config.js**
```javascript
module.exports = {
  plugins: [
    new CopyPlugin({
      patterns: [
        {
          from: 'public/**/*',
          globOptions: {
            dot: true,
            gitignore: true,
            ignore: ['**/file.*', '**/ignored-directory/**'],
          },
        },
      ],
    }),
  ],
};
```

### filter

类型：`Function` 默认值：`undefined`
>要按路径忽略文件，请使用 [`globOptions.ignore`](https://webpack.docschina.org/plugins/copy-webpack-plugin/#globoptions) 选项。

**webpack.config.js**
```javascript
const fs = require('fs').promise;

module.exports = {
  plugins: [
    new CopyPlugin({
      patterns: [
        {
          from: 'public/**/*',
          filter: async (resourcePath) => {
            const data = await fs.promises.readFile(resourcePath);
            const content = data.toString();

            if (content === 'my-custom-content') {
              return false;
            }

            return true;
          },
        },
      ],
    }),
  ],
};
```

### toType

类型：`String` 默认值：`undefined`

确定 `to` 选项指向的是目录、文件还是模板。有时很难明确 `to` 内容，例如 `path/to/dir-with.ext` 。如果要复制目录中的文件，则需要使用 `dir` 选项。我们会尽量自动判断 `type` ，因此您很可能不需要此选项。

| `'template'` | `{String}` | `undefined` | 如果 `to` [模板模式](https://webpack.docschina.org/configuration/output/#template-strings) |

### priority

类型：`Number` 默认值：`0`

允许指定复制具有相同目标名称的文件的优先级。优先级较高的文件模式将稍后复制。要覆盖文件，必须启用 [`force`](https://webpack.docschina.org/plugins/copy-webpack-plugin/#force) 选项。

**webpack.config.js**
```javascript
module.exports = {
  plugins: [
    new CopyPlugin({
      patterns: [
        // Copied second and will overwrite "dir_2/file.txt"
        {
          from: 'dir_1/file.txt',
          to: 'newfile.txt',
          force: true,
          priority: 10,
        },
        // Copied first
        {
          from: 'dir_2/file.txt',
          to: 'newfile.txt',
          priority: 5,
        },
      ],
    }),
  ],
};
```

### transformAll
类型：`Function` 默认值：`undefined`
允许你去更改多个文件的内容，并将结果保存到一个文件中。

> ℹ️ 必须指定 `to` 配置项为一个文件。只允许使用 `[contenthash]` 与 `[fullhash]` 模板字符串。

**webpack.config.js**
```javascript
module.exports = {
  plugins: [
    new CopyPlugin({
      patterns: [
        {
          from: 'src/**/*.txt',
          to: 'dest/file.txt',
          // `assets` 参数是一个符合 pattern.from ("src/**/*.txt") 静态资源数组。
          transformAll(assets) {
            const result = assets.reduce((accumulator, asset) => {
              // 静态资源内容可以使用 `source` 方法从 `asset.source` 中获取。
              // 静态资源内容是一个 [`Buffer`](https://nodejs.org/api/buffer.html) 对象，可以使用 `content.toString()` 将其转为 `String`
              const content = asset.data;

              accumulator = `${accumulator}${content}\n`;
              return accumulator;
            }, '');

            return result;
          },
        },
      ],
    }),
  ],
};
```

### 示例

#### `from` （ `glob` 、 `file` 或 `dir` ）的不同变体。
例如，考虑以下文件结构：
```
src / directory - nested / deep - nested / deepnested - file.txt;
src / directory - nested / nested - file.txt;
```
##### From is a Glob

您在“ `from` 中指定的所有内容都将包含在结果中：

**webpack.config.js**
```javascript
module.exports = {
  plugins: [
    new CopyPlugin({
      patterns: [
        {
          from: 'src/directory-nested/**/*',
        },
      ],
    }),
  ],
};
```
结果：
```
src/directory-nested/deep-nested/deepnested-file.txt,
src/directory-nested/nested-file.txt
```
如果您只想查找 `src/directory-nested/` 的内容，则只需在 `from` 中指定 `glob` 即可。要进行搜索的文件夹路径应移至 `context` 中。
**webpack.config.js**
```javascript
module.exports = {
  plugins: [
    new CopyPlugin({
      patterns: [
        {
          from: '**/*',
          context: path.resolve(__dirname, 'src', 'directory-nested'),
        },
      ],
    }),
  ],
};
```
结果：
```
deep-nested/deepnested-file.txt,
nested-file.txt
```
##### From is a Dir

**webpack.config.js**
```javascript
module.exports = {
  plugins: [
    new CopyPlugin({
      patterns: [
        {
          from: path.resolve(__dirname, 'src', 'directory-nested'),
        },
      ],
    }),
  ],
};
```
Result:
```
deep-nested/deepnested-file.txt,
nested-file.txt
```
Technically, this is `**/*` with a predefined context equal to the specified directory.

**webpack.config.js**
```javascript
module.exports = {
  plugins: [
    new CopyPlugin({
      patterns: [
        {
          from: '**/*',
          context: path.resolve(__dirname, 'src', 'directory-nested'),
        },
      ],
    }),
  ],
};
```
Result:
```
deep-nested/deepnested-file.txt,
nested-file.txt
```
##### From is a File
```javascript
module.exports = {
  plugins: [
    new CopyPlugin({
      patterns: [
        {
          from: path.resolve(
            __dirname,
            'src',
            'directory-nested',
            'nested-file.txt'
          ),
        },
      ],
    }),
  ],
};
```
Result:
```

```


```

```

#### Flatten copy
删除所有目录引用，仅复制文件名。

> ⚠️ 如果文件名相同，则结果不确定。

**webpack.config.js**
```javascript
module.exports = {
  plugins: [
    new CopyPlugin({
      patterns: [
        {
          from: 'src/**/*',
          to: '[name][ext]',
        },
      ],
    }),
  ],
};
```
结果：
```
file-1.txt
file-2.txt
nested-file.txt
```
#### 复制到新目录[](https://webpack.docschina.org/plugins/copy-webpack-plugin/#copy-in-new-directory)

**webpack.config.js**
```javascript
module.exports = {
  plugins: [
    new CopyPlugin({
      patterns: [
        {
          // When copying files starting with a dot, must specify the toType option
          // toType: "file",
          to({ context, absoluteFilename }) {
            return `newdirectory/${path.relative(context, absoluteFilename)}`;
          },
          from: 'directory',
        },
      ],
    }),
  ],
};
```
结果：
```
"newdirectory/file-1.txt",
"newdirectory/nestedfile.txt",
"newdirectory/nested/deep-nested/deepnested.txt",
"newdirectory/nested/nestedfile.txt",
```
#### 跳过通过压缩器运行 JavaScript 文件 

如果您需要简单地将 `*.js` 文件“原样”复制到目标位置，而无需使用 Terser 对其进行评估和最小化，则此功能非常有用。

**webpack.config.js**
```javascript
module.exports = {
  plugins: [
    new CopyPlugin({
      patterns: [
        'relative/path/to/file.ext',
        {
          from: '**/*',
          // Terser skip this file for minimization
          info: { minimized: true },
        },
      ],
    }),
  ],
};
```
##### `monorepos`yarn workspaces

当时用 `yarn workspaces` 或者 `monorepos` 时，由于包提升方式不同，node_modules 的相对复制路径可能会失效。 为了避免这种情况，请使用 `require.resolve` 指定复制路径。

**webpack.config.js**
```javascript
module.exports = {
  plugins: [
    new CopyPlugin({
      patterns: [
        {
          from: `${path.dirname(
            require.resolve(`${moduleName}/package.json`)
          )}/target`,
          to: 'target',
        },
      ],
    }),
  ],
};
```
